# Spec: Invoice PDF and Email Delivery

**Ticket:** IF-7

> **MVP scope:** All requirements. Dev mailer is `log`; no real SMTP needed. Test plan: Pest only (skip Vitest).

## 1. Purpose
Produce a professional PDF and deliver the invoice to the client with a secure link to view and pay.

## 2. User Stories
- As an Accountant, I can download an invoice as PDF.
- As an Accountant, I can email the invoice to the client.
- As a client, I can open a link to view the invoice without logging in.

## 3. Functional Requirements
- FR-1: PDF generated by DomPDF from a Blade template (layout in `../ai-context/ui-context.md`)
- FR-2: Download route returns `application/pdf`, filename `INV-0001.pdf`
- FR-3: "Send" action queues `SendInvoiceEmail`: Markdown Mailable with PDF attached and a "View invoice" button
- FR-4: Sending moves status draft to sent, sets `sent_at`, fires `InvoiceSent`
- FR-5: Resend allowed for sent/overdue/partially_paid invoices (does not change status)
- FR-6: Public page `/i/{token}` via signed URL (Inertia React page, public layout) shows invoice read-only, with "Download PDF" and "Pay now" (if balance > 0)
- FR-7: Email recipient defaults to the client email; can be overridden before sending
- FR-8: Void/paid invoices show a status stamp on PDF and public page

## 4. Business Rules
- Client must have an email (or one is entered) to send
- Public page exposes only that invoice and company branding; no other client data
- Signed URL can expire (default 30 days) and be regenerated by resending
- PDF content uses item snapshots, not live product data

## 5. Data Model
`invoices.public_token`, `sent_at`. Uses the `jobs` queue table.

## 6. Permissions
Download: all roles. Send: Owner, Accountant. Public page: anyone with the valid link.

## 7. UI / UX
"Send" modal with To, Subject, Message (prefilled), preview of attachment. Success toast. Public page is clean, mobile friendly, and shows payment status.

## 8. Edge Cases
- Mail fails: job retries with backoff; after final failure the invoice stays in its previous state and the user is notified
- Tampered or expired link returns 403 with a friendly page
- Special characters in names break PDF fonts: use a UTF-8 capable font (DejaVu Sans)
- Sending twice quickly: guard against double dispatch

## 9. Acceptance Criteria
- [ ] PDF matches layout and totals
- [ ] Email queued, contains PDF and link
- [ ] Status and `sent_at` updated only after successful dispatch rules defined above
- [ ] Tampered link rejected
- [ ] Public page leaks nothing else

## 10. Test Plan
Mail::fake, Queue::fake, signed URL tests, PDF response header and content test, authorization tests, tenant isolation.

## 11. Out of Scope
Custom email templates, invoice branding themes, WhatsApp/SMS delivery.
